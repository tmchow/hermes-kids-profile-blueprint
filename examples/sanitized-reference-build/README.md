# Sanitized reference report structure

This example shows the required shape of a private build report. It does not represent a real child, account, provider, deployment, or successful build. Every result is `NOT VERIFIED` on purpose.

## Build summary

- Profile name: `kids-1`
- Hermes version: `NOT VERIFIED`
- Blueprint commit: `NOT VERIFIED`
- Access mode: Parent-controlled messaging gateway
- Additional isolation controls: `NOT VERIFIED`
- Interface and scope: Direct messages only
- Model and provider: `NOT VERIFIED`
- Production process owner: `NOT VERIFIED`
- Production environment source types: `NOT VERIFIED`
- Capability tier: Text chat
- Static personalization: Age band and broad interests only
- Autonomous memory: Disabled by intent, runtime `NOT VERIFIED`
- Context-engine tools: Disabled by intent, runtime `NOT VERIFIED`
- Session search: Disabled by intent, runtime `NOT VERIFIED`
- Search and media: Disabled by intent, intake rejection `NOT VERIFIED`
- Provider credential: Dedicated project credential planned, source `NOT VERIFIED`
- Retention contract: Manual deletion with no guaranteed deadline

## Critical checks

Each private report must include all current critical checks. Use rows like these:

- Check: Production credential boundary
  - Check result: `NOT VERIFIED`
  - Evidence type: Production service environment and credential-source report
- Check: Exact resolved model tools
  - Check result: `NOT VERIFIED`
  - Evidence type: Sorted runtime tool names for the child interface
- Check: Sender and scope authorization
  - Check result: `NOT VERIFIED`
  - Evidence type: Child, parent, unauthorized sender, and unauthorized scope results
- Check: Child command intake boundary
  - Check result: `NOT VERIFIED`
  - Evidence type: Idle and active-turn results for child `/help`, `/whoami`, `/status`, `/context`, other commands, and the parent admin route
- Check: No child pre-authorization administrative state
  - Check result: `NOT VERIFIED`
  - Evidence type: State inspection plus approval-like and clarify reply results
- Check: Text-only media rejected before preprocessing
  - Check result: `NOT VERIFIED`
  - Evidence type: Adapter or proxy rejection plus negative cache and provider evidence

The real report must repeat this structure for every critical check in `baseline/READINESS-CRITERIA.md`.

## Overall readiness

- Overall readiness label: `FAIL`
- Reason: Critical checks remain unverified.

## Residual risks

- Model behavior is probabilistic.
- The gateway process retains its operating-system permissions.
- Provider and messaging-platform copies follow their configured terms.
- Behavioral evals must run again after a model or policy change.

## Stop action

The private report must contain the exact production command or administrative action. This public structure omits machine-specific service details.
